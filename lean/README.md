# Lean formalization

Written by Claude Fable 5.2 (AI, orchestrator), 2026-11-14. Not human-reviewed.

This folder is a Lean 4 project that depends on Mathlib. A statement listed below as **checked** is one that Lean has compiled without `sorry` and with no axioms beyond Lean's three standard ones. Nothing else in this folder counts as verified.

## In one paragraph

Lean has checked the **divisibility half** of the theorem, by the tree-symmetry argument of the main paper (Steps 1 and 2): for a prime p, p^t divides the number of p-ary trees with m leaves, where t = (s_p(m) − 1)/(p − 1); the same for the trees that represent q-ary trees, q = p^k. For p = 2 this is tied to Mathlib's own Catalan numbers: 2^(s_2(n+1) − 1) divides C_n. Lean has **not** checked that the power is exact (Steps 3 and 4), and it has checked nothing of the accounting proof or the Frobenius proof.

## Not checked by Lean

| Part | Why it matters |
|---|---|
| **Step 3** (the minimal classes are the atom trees) and **Step 4** (their number is not divisible by p; the carry is a collapsing cherry) | Without these Lean has v_p ≥ t, not v_p = t. The exact valuation and the residue (−1)^t/∏ m_j! are not machine-checked. |
| Lemma "Blocked form": q-ary trees with n nodes correspond to p-ary trees with all leaves at depths divisible by k | The prime-power statement above is about the p-ary trees; the translation to q-ary trees is the paper's lemma. |
| The closed formula: the number of q-ary trees with n nodes is binom(qn, n)/((q − 1)n + 1) | Classical. In Lean it is tied to a known sequence only for p = 2 (Catalan numbers); Mathlib has no Fuss–Catalan numbers. |
| Lemma "Normal form": the relation generated by single rotations equals the relation `Rot` used here | `Rot` is defined directly in the normal form. The divisibility statements do not mention `Rot`, so they do not depend on this lemma. |
| The accounting proof and the Frobenius proof | Nothing of either is formalized. |

## What one has to trust

- For `pow_dvd_card_trees`: three short definitions (`PTree`, `PTree.leaves`, `ds`, about ten lines in all), the Lean kernel and Mathlib. The statement does not mention rotations at all; they appear only inside the proof.
- For `two_pow_digitSum_sub_one_dvd_catalan`: nothing of ours. Both sides (`catalan`, `Nat.digits`) are Mathlib's definitions.
- Lean checks that each proof follows from the definitions **as written in the file**. Whether a definition says what the paper means is a matter of reading the definitions.
- If no t with (p − 1)·t + 1 = s_p(m) exists, the divisibility theorem says nothing; in that case m is not ≡ 1 (mod p − 1) and there are no trees with m leaves.

## How to check

Lean is installed with `elan` in the user's home folder (`~/.elan`), not on the PATH. From this folder:

    export PATH="$USERPROFILE/.elan/bin:$PATH"     # Git Bash on Windows
    lake exe cache get                             # once: fetch Mathlib's prebuilt files
    lake build                                     # compiles everything; any error or `sorry` shows here

`lean-toolchain` pins the Lean version (`leanprover/lean4:v4.36.0-rc2`); `lake-manifest.json` pins the Mathlib commit. A full build takes about two minutes once Mathlib's prebuilt files are present. Disk use on this machine: about 3.2 GB for the toolchain (`~/.elan`) and about 7 GB for `lean/.lake` (Mathlib and its prebuilt files), which is not in git.
